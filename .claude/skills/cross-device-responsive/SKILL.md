# 跨端自适应（小程序 / Web / App 通用）

目标：同一套设计在 320px 手机、平板、PC 全宽窗口、折叠屏、分屏、横竖屏下都**不溢出、不裁切、不抖**；大屏放大主体，控件保持手指尺寸。

## 0. 心智模型：分三层，不要混着改

| 层 | 决定什么 | 典型产物 |
| --- | --- | --- |
| 设计层 | 谁是主体、谁是控件、谁是装饰 | 内容优先级、触摸目标下限、装饰是否跟随缩放 |
| 布局层 | 容器多大、怎么排列、何时重排 | 容器尺寸函数、栅格、断点、换行策略 |
| 实现层 | 单位、缩放、测量、动画 | token、rpx/rem/pt、zoom/transform、缓存 |

出问题时先定位在哪一层：**“大屏字巨大”是实现层，“两列挤成一列”是布局层，“按钮比钟还抢眼”是设计层**。三层混改必然越改越乱。

## 1. 六条通用原则

1. **尺寸只有一个口径。** 会变的尺寸收敛到一个函数/一组 token（容器宽高、字号档位、间距档位）。同一个组件不允许在四个页面各写一份倍率——这是“同一个钟四处四种大小”的唯一根因。
2. **容器先行，内容适配。** 先算容器（只跟窗口/父容器有关），再让内容按自然尺寸塞进去。容器不动 → 换内容/换皮肤/换状态时，周围组件不跳。
3. **主体放大，控件锁定。** 大屏只放大“看的东西”（时钟、图表、卡片正文、海报数字）；按钮、输入框、开关保持手机档物理尺寸，只调整位置和留白。触摸目标下限：移动端 44×44pt / 88×88rpx，桌面 32×32px 且鼠标可达。
4. **流式优先，断点兜底。** 主布局用 `%`、`flex`、`grid`、`clamp()` 吸收连续变化；断点只做“档位切换”（换列数、换排列），不做逐像素补丁。
5. **空间必须真实预留。** `transform: scale()` 不改变布局，放大后一定压住下面的东西；要真占位就用布局尺寸、`zoom`（Web）、或“外层固定尺寸 + 内层缩放”（App/RN/Flutter）。
6. **内容与尺寸解耦。** 切换内容时，新内容的尺寸必须在同一帧就位（缓存倍率 + 同一帧提交），否则就是屏闪和抖动。

## 2. 单位与缩放：一张映射表

| 端 | 长度 | 字号 | 与 px 的关系 | 主要陷阱 |
| --- | --- | --- | --- | --- |
| 微信小程序 | `rpx`（750 基准） | `rpx` | 1rpx = 屏宽/750 | 宽窗口按宽度换算，1700px 时 1rpx≈2.27px，全部翻 2.3 倍 |
| 小程序横屏 | 只用 `px` | `px` | — | 812 宽时 1rpx≈1.08px，128rpx 的 64px 会变 138px |
| Web / H5 | `rem`、`%`、`vw`、`fr`、`clamp()` | `rem` / `clamp()` | 1rem = 根字号 | 根字号被用户改大；`100vh` 在移动端地址栏下不准，用 `dvh` |
| iOS 原生 | `pt`（Auto Layout 约束） | `pt` + Dynamic Type | 1pt≈2~3px | 写死高度遇大字号被裁；safeArea 未处理 |
| Android 原生 | `dp` | `sp` | 1dp≈1~4px | 用 dp 写字号，用户调字号不跟随 |
| React Native | 逻辑像素（≈dp） | `fontSize` + `allowFontScaling` | `PixelRatio` 换算 | 默认 `flexShrink:1`、无 `minWidth:0` 概念，长文本会顶宽 |
| Flutter | 逻辑像素 | `textScaleFactor` | `MediaQuery` | 固定 `height` 容器遇大字号溢出 |

统一换算经验：**手机基准下 `1rpx ≈ 0.5~0.56px`**，据此把设计稿的 rpx 值折成桌面 px 档。

## 3. 断点与容器查询

- 尺寸断点参考：320 / 375（基准）/ 414 / 600 / 768 / 1024 / 1280 / 1700，同时覆盖横屏与自由拉伸窗口。
- 能力强的平台优先用**容器查询**（Web `@container`、Flutter `LayoutBuilder`、RN `onLayout`），让组件按自身可用宽度响应，而不是按整页宽度——同一个卡片在窄栏和宽栏里表现才正确。
- 断点只回答三个问题：**几列？横排还是竖排？显示还是隐藏次要信息？** 其余交给流式。
- 折叠屏/分屏本质是“窗口连续变化”，必须监听 resize（Web `resize`、小程序 `onWindowResize`、RN `Dimensions`、Flutter `MediaQuery`），不能只依赖首次渲染。

## 4. 四种自适应模式（按内容性质选）

| 模式 | 适用 | 做法 |
| --- | --- | --- |
| 拉伸 fluid | 单列正文、进度条、图表 | `width:100%`、`flex:1`、`clamp()` |
| 换行 wrap | 标签、按钮组、筛选项 | `flex-wrap: wrap`，禁止靠 shrink 把字挤没 |
| 重排 reflow | 卡片列表、表单 | 2 列 → 1 列；横排 → 竖排 |
| 替换 swap | 差异过大的场景 | 大屏用图表、小屏用数字摘要（同一数据，两种呈现） |

关键细节：多列网格一律 `repeat(n, minmax(0, 1fr))`。只写 `1fr` 会被长内容顶宽，这条在 CSS / RN / Flutter Grid 都成立。

## 5. 缩放与测量（跨平台做法）

- **Web**：`transform: scale()` 不占位 → 要么用外层 `aspect-ratio` 盒子预留空间，要么用 `zoom`（非标准但 Chromium/Safari 可用），要么直接用 `clamp()` 算字号。
- **小程序**：`zoom` 可真实改布局；`transform` 只适合纯视觉强调。
- **iOS/Android/RN/Flutter**：用“外层固定尺寸容器 + 内层 `scale` 变换 + `transformOrigin` 居中”，或直接按容器算字号；不要指望缩放改变父布局。
- **测量原始尺寸**：`rect / 当前scale`（transform 会被算进 rect），缓存 key 用 `组件|形态|档位`。
- **过渡期间禁止测量**：动画中的 rect 是中间态，写进缓存会永久错（典型症状：退出全屏后组件莫名变小）。加“形变中”门闩，延后重试。
- **倍率交接**：从一种缩放机制切到另一种（全屏 transform → 页面 zoom）要三段式：保持旧值 → 收到新值 → 同一帧切换，中间不留空档。

## 6. 溢出与挤压：通用防护清单

- 所有 flex 子项 `min-width: 0`（Web/小程序）；RN 用 `flexShrink: 1` + `numberOfLines`；Flutter 用 `Expanded/Flexible`。
- 卡片 `width: 100%` + `box-sizing: border-box`；图片 `max-width: 100%` + 固定比例容器。
- 行内按钮显式收敛：`width: auto`、`min-width: 0`、`flex: 0 1 auto`、`max-width: 100%`。
  **微信原生 `button` 默认宽度约 184px**；Web `<button>` 常带默认 padding/min-width；iOS `UIButton` 有 intrinsic size——都要显式覆盖。
- 放不下就换行，不要 shrink 到文字消失；长文本 `overflow-wrap: anywhere` + 行数截断。
- 容器兜底 `overflow-x: hidden`；表格/图表单独横向滚动，禁止整页横滚。
- `flex-wrap + space-between` 最后一行会被拉满 → 用 grid 或 `flex-start`。

## 7. 安全区、固定元素与滚动高度

- 刘海/状态栏/手势条：Web/小程序 `env(safe-area-inset-*)`；iOS `safeAreaLayoutGuide`；Android `WindowInsets`；RN `SafeAreaView`；Flutter `SafeArea`。
- **滚动区不要 `calc(100vh - 底栏)`**：安全区算法两侧不一致会露出死白带。用 `height: 100dvh` + `padding-bottom: 底栏 + 安全区 + 余量`，让内容从底栏后面穿过。
- **祖先有 `transform/filter/perspective/will-change` 时，内部 `position: fixed` 失效**（Web/小程序都成立）→ 底部常驻按钮做 flex 页脚，别靠 fixed。
- 固定浮层的定位值不要用随宽度缩放的单位（rpx/rem/vw），宽屏会成倍偏移；用 px/pt + 安全区。

## 8. 文字与数字稳定

- 数字：`font-variant-numeric: tabular-nums` + 固定宽度（`ch` 或 `min-width`），否则逐帧变化的毫秒会把整行推得抖。
- 逐帧文本容器居中，避免左右摆；时间显示定宽（如 4.2ch）。
- 字号下限：小程序 ≥18rpx、Web ≥12px、移动端正文 ≥14sp；降级用颜色/字重，不要靠缩字号。
- 大字号/无障碍：iOS Dynamic Type、Android `sp`、Web 根字号放大、Flutter `textScaleFactor` 各测一遍，行高用相对单位。
- 伪元素与描边：`text-shadow`、`-webkit-text-stroke`、`box-shadow` 的偏移若写 rpx/rem，宽屏会与 px 化字号脱节（描边把空心字填死）——大屏档要换 px 或整体缩放。

## 9. 大屏适配的三件事（桌面/平板/折叠屏展开）

1. **判定**：平台标识 + 可用宽度双条件（如 `platform==='mac'|'windows'` 且 `width>600`），给根节点一个状态类，不要靠 UA 猜。
2. **换档**：宽屏把 rpx/rem 化的字号、圆角、阴影、圆圈统一换成 px/pt 档；只限宽不改字号＝无效。
3. **限宽 + 留白**：表单 960~1040px、阅读 900px、卡片列表 1280px；同时补纵向 padding，否则“只收窄没垫高”会被判比例不对。
   - 页面级背景不要挂在被限宽的子容器上（两侧会露边），挂到根/伪元素 `position: fixed; inset: 0`。
   - 自定义组件拿不到页面根类时，组件自带桌面状态（生命周期里同步）或用同元素选择器。

## 10. 架构层：自适应也是状态管理

- **入口不能依赖首页状态。** 首页可自定义时，`switchTab` 回首页会落到用户当前固定的那一屏，而不是功能本身 → 给功能独立页，或跳转时用显式 `mode/flag` 强制进入对应视图。
- **数据只留一个入口**：`getXxx()` / `startXxx()` 收敛在应用层，页面不再各自解析存储；老格式兼容只写一处。
- **响应式状态向下传**：把 `isDesktop / containerWidth / breakpoint` 作为显式状态传给组件，组件内部不各自测窗口。
- **布局分支不超过两处**：同一屏的结构差异（横/竖、宽/窄）集中在一个模板分支里，避免四份近似代码各自漂移。

## 11. 验收矩阵

| 维度 | 必测 |
| --- | --- |
| 尺寸 | 320 / 375 / 414 / 600 / 768 / 1024 / 1280 / 1700 |
| 方向 | 竖屏、横屏，以及旋转回来的“单位基准残留” |
| 窗口 | 拖拽拉伸（非重启）、分屏、折叠屏展开 |
| 内容 | 空态、超长文本、极长数字、图片缺失 |
| 状态 | 换皮肤/换主题、切 tab、进出全屏、键盘弹起 |
| 无障碍 | 大字号、深色模式、减少动效 |
| 边界 | 无横向滚动、无裁切、无重叠、按钮不贴边、底部不被浮层压住 |

每次改完尺寸档位，**按源码顺序核对“后写的是否覆盖了想保留的那条”**（“手机上按钮偏小”常常是矮窗口媒体查询干的）。

## 12. 反模式清单

- 用 `transform: scale()` 当布局放大（必然压住下方）。
- 只给根容器 `max-width` 就宣称适配了大屏（字号仍是 rpx/rem 放大版）。
- 同一个组件在 N 个页面各写一份尺寸。
- 过渡动画中测量并写缓存。
- flex 子项不写 `min-width: 0`。
- 滚动区扣 `100vh - 底栏`。
- 固定浮层用 rpx/rem 定位。
- 用断点逐像素修字号（应当整体换档）。
- 功能入口靠“回首页”实现（首页一旦可自定义就失效）。
